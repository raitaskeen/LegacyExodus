## Code read of the fixes

- **#198:**
  - `analyzer-fingerprint.ts` computes the default-root fingerprint synchronously at module evaluation. Validation uses that loaded value. `file-discovery-projection.ts` recomputes it before signing and omits `analyzer` if it changed, which makes the snapshot `ANALYZER_MISMATCH` everywhere.
  - An injected identity is read once, at `createSnapshotTrust`.
  - Edit-then-revert during a run is benign, because the output came from the loaded code.
  - No new hole found.
  - Cost: two synchronous source hashes per process (load, then each signing), measured at roughly 15–50 ms each.
- **#199:** the preload captures the identity before any test file loads the engine. The helper rechecks before writing a record. The preload applies only under `bun test`, and only test files import the helper. No new hole found.
- **#198 residual (edit during startup): ACCEPTABLE.**
  - Measured: the fingerprint is taken 0.15–0.24 s after process start, at the end of module loading.
  - Only an edit landing inside that slice escapes the recheck.
  - It is low probability and heals at the next analyzer change. It is comparable to #199's own residual.
  - Optional hardening: fingerprint at the CLI entry point before importing the engine; then the existing recheck would also catch edits during loading.
