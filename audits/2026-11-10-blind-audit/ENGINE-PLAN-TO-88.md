## 3. The harness: what proves each step

| ID | Harness | What it measures | Gate |
|---|---|---|---|
| H1 | `benchmarks/cli.ts coverage` | Per corpus: proven, by type, external, and unknown-by-reason shares of all calls | Published on every PR; a drop in the accounted-for or proven share fails, unless explained |
| H2 | **Call oracle** | Run Express's and Fastify's own test suites with a call tracer (a `--require` hook that records call site → function reached). Compare with the engine | Precision: any RESOLVED call the trace contradicts **fails the PR**. Recall: reported per corpus |
| H3 | Adversarial cases | Every audit probe and every fixed bug is a conformance case (done for XA-01 to XA-06) | Already a gate |
| H4 | Taint benchmark | Known vulnerabilities in public Node apps (SecBench.js-style set, NodeGoat, Juice Shop). Semgrep CE runs on the same set | Precision and recall per sink class, published |
| H5 | CFG oracle | V8 block coverage from the H2 test runs: every executed block must be in the CFG and reachable | Any miss fails |
| H6 | Scale | Nightly Ghost and one large TypeScript corpus. Fresh, reuse and incremental time and memory | Budgets: Ghost fresh ≤ 360 s and ≤ 2,560 MiB, as today |
| H7 | Determinism matrix | The same corpora on Linux and Windows | Fact files byte-identical across both |
| H8 | Docs truth | Regenerates the README and Current Implementation numbers from H1, H4 and H6 output | A mismatch fails |

## 6. Decisions needed before Phases A and B

1. Add the evidence states **EXTERNAL** and **RESOLVED BY TYPE** to the contract (ADR plus a manifest schema bump).
   *Recommended: yes.*
2. Run the corpora's own test suites in CI for H2 and H5. This installs their dev dependencies from pinned lockfiles
   and adds a few minutes per PR. *Recommended: yes, on every PR for Express and Fastify; nightly for heavier ones.*
3. TypeScript checker: on by default within budget, or opt-in with a flag. *Recommended: on by default once D1
   meets the H6 budget; opt-in until then.*
4. Publish the H4 comparison with Semgrep CE. *Recommended: yes, both wins and losses.*
